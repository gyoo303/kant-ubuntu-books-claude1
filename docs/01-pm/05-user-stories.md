## M1 쇼핑 기반

### US-01: 방문자로서, 이 책방이 어떤 곳인지 느끼기 위해, 메인에서 책방 분위기와 4개 테마 입구를 보고 싶다.
- 근거: REQ-001, 002, 004, 007, 017, 045 · KANT-R1, C2
1. 방문자가 `/`에 들어온다.
2. 공통 Header(로고, 테마 서가, 책방 소개, 구독, 장바구니, 로그인/마이페이지)와 Footer가 보인다.
3. 책방 한 줄 소개, 4개 테마(자연·식문화·생태·로컬) 입구, 추천 책 카드 몇 권, 손편지 구독 안내가 보인다.
4. 테마 입구·책 카드·구독 안내를 누르면 새로고침 없이 해당 화면으로 이동한다.
- REJ-01: 상품 데이터를 불러오지 못함 → 추천 책 영역에 안내 문구, 나머지 화면은 정상 표시
- INV: —

### US-02: 방문자로서, 책방의 결을 알기 위해, 책방 소개를 읽고 싶다.
- 근거: REQ-002, 006 · Q-015
1. Header의 책방 소개를 누른다. 2. 소개 글·사진(임시 원고, "예시" 표시)이 보인다.
- REJ-02: 사진 로드 실패 → 글은 그대로, 사진 자리는 비율을 유지한 대체 영역
- INV: —

### US-03: 방문자로서, 마음에 맞는 책을 찾기 위해, 전체 책 목록과 테마별 서가를 보고 싶다.
- 근거: REQ-007, 008 · Q-007 · KANT-R5, C9~C11
1. `/products`에서 전체 책이 카드 목록으로 보인다(표지, 제목, 저자, 가격, 테마, 품절 여부).
2. 테마 하나를 고르면 그 테마 책만 보인다. 다시 "전체"를 고르면 전체가 보인다.
3. 카드를 누르면 상세로 이동한다.
- REJ-03: 테마에 책이 0권 → "이 서가는 아직 준비 중입니다" 안내
- REJ-04: 존재하지 않는 테마 값 → 전체 목록과 안내
- INV: INV-08 (품절 카드는 품절 표시)

### US-04: 방문자로서, 책방지기의 마음을 먼저 듣기 위해, 상세 화면 맨 위에서 책방지기 노트를 읽고 싶다.
- 근거: REQ-009 · KANT-R6, C12, C14
1. `/products/[id]`에 들어온다.
2. 화면 맨 위에 책방지기 노트가 본문보다 큰 글씨로 보인다.
3. 그 아래 표지, 제목, 저자, 출판사, 테마, 가격, 재고 상태, [장바구니 담기].
4. 출판사 소개(설명)는 노트 아래에 접힌 상태로 있다.
- REJ-05: 없는 ID → 크래시 없이 "상품을 찾을 수 없습니다" + 목록으로 가는 링크
- REJ-06: 품절(재고 0) → [장바구니 담기] 비활성 + "품절" 표시
- INV: INV-08

## M2 회원

### US-05: 회원으로서, 가입 절차의 피로 없이 이용하기 위해, 카카오나 네이버로 로그인하고 로그아웃하고 싶다.
- 근거: REQ-015, 016 · →ARCH-01
1. [로그인]을 누르면 카카오·네이버 버튼 두 개만 보인다.
2. 하나를 골라 제공자 동의를 마치면 로그인 전 보던 화면(또는 주문서)으로 돌아온다. 처음이면 회원이 자동으로 만들어진다.
3. Header에 마이페이지·로그아웃이 보인다. 로그아웃하면 비회원 상태로 돌아간다.
- REJ-07: 제공자 화면에서 취소·거부 → 로그인 화면으로 돌아와 "로그인이 취소되었습니다"
- REJ-08: 제공자 오류 → 다시 시도 안내, 다른 제공자 버튼 유지
- INV: —

### US-06: 회원으로서, 책을 받기 위해, 배송지를 입력하고 고치고 싶다.
- 근거: Q-011 · ASM-015
1. 첫 주문서 또는 구독 신청에서 이름·연락처·우편번호·주소·상세주소를 입력한다(수집 목적·보관 기간 안내 문구와 동의 체크).
2. 저장된 배송지는 다음 주문·구독에 자동으로 채워진다.
3. 마이페이지에서 고칠 수 있다. 이미 발송된 주문·회차의 배송지는 바뀌지 않는다.
- REJ-09: 필수 항목 누락·연락처 형식 오류 → 해당 칸 아래 안내, 저장 안 됨
- REJ-10: 동의하지 않음 → 저장 안 됨
- INV: INV-11

### US-07: 책방지기로서, 작업을 하기 위해, 관리자 화면에 들어가고 싶다.
- 근거: REQ-037 · ASM-021, D-012 · →ARCH-02
1. 책방지기가 정해진 방식(→ARCH-02)으로 로그인한다.
2. 관리자 첫 화면에서 서재 작업 화면, 주문 목록, 주소록, 재고, 인사 편지, 작별 편지함으로 갈 수 있다.
- REJ-11: 책방지기가 아닌 회원·비회원이 관리자 경로 접근 → 접근 거부(로그인 또는 메인으로 이동), 관리자 데이터 미노출
- INV: INV-13

## M3 구매

### US-08: 방문자로서, 둘러보다 마음에 든 책을 모아 두기 위해, 장바구니에 담고 수량을 바꾸고 빼고 싶다.
- 근거: REQ-013 · Q-006, D-004, D-026
1. 상세에서 [장바구니 담기] → "장바구니에 담았습니다" 안내, Header 장바구니 개수 증가.
2. `/cart`에서 책별 수량 증감, 빼기, 합계(책 금액 + 배송비 임시 금액)를 본다.
3. 비회원으로 담은 장바구니는 로그인한 뒤에도 남아 있다.
- REJ-12: 재고보다 많은 수량 → 재고 수까지만, "남은 수량은 n권입니다"
- REJ-13: 담아 둔 책이 그 사이 품절 → 해당 줄에 "품절" 표시, 합계·주문에서 제외
- INV: INV-08, INV-16

### US-09: 회원으로서, 고른 책을 받기 위해, 신용카드나 간편결제로 주문하고 싶다.
- 근거: REQ-014 · Q-017, D-002 · →ARCH-05
1. 장바구니에서 [주문하기] → 비회원이면 로그인(US-05) 후 주문서로 돌아온다.
2. 주문서에 책 목록, 배송지(US-06), 금액(서버 계산), 환불 안내(임시 문구)가 보인다.
3. [결제하기] → 토스페이먼츠 결제창(테스트 모드)에서 카드·간편결제로 인증.
4. 서버가 금액을 대조해 승인하면 주문 `paid`, 재고 차감, 장바구니에서 해당 책 제거, 결제 완료 화면.
- REJ-14: 결제창 닫기·인증 실패 → 실패 화면 "결제가 완료되지 않았습니다", 장바구니 유지, 주문 `cancelled`
- REJ-15: 금액 불일치 → 승인하지 않음, 실패 화면
- REJ-16: 결제 직전 재고 부족 → 승인하지 않음, 어떤 책이 부족한지 안내
- REJ-17: 같은 결제 성공 응답이 두 번 들어옴 → 한 번만 확정
- REJ-18: 배송지 없음 → 배송지 입력 전에는 [결제하기] 비활성
- INV: INV-05, INV-06, INV-07, INV-08, INV-16

### US-10: 회원으로서, 주문한 책을 확인하기 위해, 마이페이지에서 주문 상태를 보고 발송 전이면 취소하고 싶다.
- 근거: Q-004, D-007, D-022
1. 마이페이지 주문 내역에 주문별 날짜·책·금액·상태 글자(주문 확인 / 발송됨 / 주문 취소됨)가 보인다. 창가 그림은 쓰지 않는다.
2. `주문 확인` 주문에 [주문 취소] → 전액 환불, 재고 복구, `주문 취소됨`.
- REJ-19: `발송됨` 주문 → [주문 취소] 없음 (직접 요청 시에도 거부)
- REJ-20: 환불 실패 → 상태 그대로 `주문 확인`, "취소하지 못했습니다. 잠시 후 다시 시도해 주세요"
- REJ-21: 같은 주문 취소 두 번 → 한 번만 환불
- REJ-22: 다른 회원의 주문 → 보이지 않음, 취소 거부
- INV: INV-11, INV-18

### US-11: 책방지기로서, 장바구니로 들어온 주문을 보내기 위해, 주문 목록에서 배송지를 보고 발송 처리하고 싶다.
- 근거: Q-004, D-011
1. 주문 목록에 `주문 확인` 주문이 오래된 순으로 보인다(주문일, 이름, 책·수량, 배송지).
2. [발송 처리] → `발송됨`, 회원 마이페이지에 반영.
- REJ-23: `paid`가 아닌 주문 → [발송 처리] 없음
- REJ-11 (권한)
- INV: INV-05, INV-13

## M4 구독

### US-12: 회원으로서, 취향 설문 대신 내 마음을 전하기 위해, 편지를 써서 정기구독을 신청하고 싶다.
- 근거: REQ-018, 019, 020 · Q-001, Q-002, Q-011, D-002, D-003, D-023
1. 구독 안내에서 [손편지 띄우기] → 비회원이면 로그인.
2. 편지지 화면: 체크박스·설문 없이 자유 글 한 칸(마음 날씨, 읽고 싶은 책의 결), 구독료(임시 금액)·매달 결제일(오늘 날짜 기준) 안내, 배송지.
3. [우체통에 편지 넣기] → 자동결제 등록·첫 결제(테스트 모드).
4. 결제 확정 → 구독 `active`, 회차 1 `letter_arrived`, 편지 저장.
5. 봉투가 닫히며 우체통으로 들어가는 전환이 재생되고, 끝나면 완료 메시지와 [마이페이지 창가 보기].
- 관찰 가능한 행동: 결제 확정 후 0.3초 안에 전환 시작, 3초 안에 완료 메시지. 움직임 줄이기 설정이면 전환 없이 바로 완료 메시지.
- REJ-24: 빈 편지·글자 수 초과 → 제출 안 됨, 안내
- REJ-25: 이미 활성 구독이 있음 → 신청 화면 대신 "이미 구독 중입니다"와 마이페이지 링크
- REJ-26: 자동결제 등록·첫 결제 실패 → 구독·회차 생성 안 함, 쓴 편지는 화면에 남음, 실패 안내 (애니메이션 없음)
- REJ-27: 배송지 없음 → 입력 전 제출 불가
- INV: INV-05, INV-16, INV-17

### US-13: 회원으로서, 매달 신경 쓰지 않고 책을 받기 위해, 자동결제로 회차가 열리길 원한다.
- 근거: Q-001, Q-018, D-003, D-021
1. 신청일 기준 매달 같은 날(없는 날이면 말일) 자동결제가 시도된다.
2. 성공 → 새 회차 생성. 보관된 다음 회차 편지가 있으면 `letter_arrived`, 없으면 `awaiting_letter`.
3. 실패 → 회차 없이 구독 `ended`, 마이페이지에 "결제가 되지 않아 구독이 마무리되었습니다"와 다시 신청 링크.
- REJ-28: 해지·종료된 구독 → 결제 시도 안 함
- REJ-29: 같은 달 결제가 두 번 시도·확정됨 → 회차는 하나만
- INV: INV-05, INV-07, INV-19

### US-14: 회원으로서, 이번 달 마음을 전하기 위해, 다음 회차 편지를 보내고 싶다.
- 근거: Q-002, D-014, D-023, D-027
1. 마이페이지 창가가 `awaiting_letter`(또는 언박싱을 마친 상태)일 때 [편지 쓰기]가 보인다.
2. 편지지 화면에서 쓰고 [우체통에 편지 넣기] → US-12와 같은 전환. 결제는 없다.
3. 편지는 아직 `reading`이 아닌 가장 이른 회차에 붙고, 없으면 다음 회차 편지로 보관된다.
- REJ-30: 활성 구독이 아님 → [편지 쓰기] 없음, 구독 안내로
- REJ-31: 다음 회차 편지가 이미 보관돼 있음 → 새 편지 대신 보관된 편지를 고치는 화면이 열린다 (회차당 1통, D-027)
- INV: INV-10, INV-11

### US-15: 회원으로서, 책방지기가 내 편지를 읽고 있음을 느끼기 위해, 마이페이지 서점 창가를 보고 싶다.
- 근거: REQ-021~024 · Q-020, D-010, D-015
1. 마이페이지에 서점 창가 그림이 가장 최근 회차 상태로 보인다.
   - `awaiting_letter`: 어두운 창 + [편지 쓰기]
   - `letter_arrived`: 어두운 창 + "편지가 책방에 도착했어요"
   - `reading`: 촛불 켜진 창
   - `shipped`: 촛불 꺼짐, 창가 우체통 불빛 + "책이 서점 문을 나섰습니다"
   - `unboxed`: `awaiting_letter`와 같은 모양
2. 페이지를 다시 열면 최신 상태가 보인다(실시간 아님).
3. 택배 송장 번호·배송 단계 숫자는 보이지 않는다.
- REJ-32: 구독 이력 없음 → 창가 대신 구독 안내
- REJ-33: 구독 `cancelled`·`ended` → 마지막 상태 그림 + 마무리 안내 (이미 발송된 책은 서가에서 언박싱 가능)
- INV: INV-09, INV-10

### US-16: 책방지기로서, 손님의 마음을 읽기 위해, 작업 화면 위쪽에서 편지를 읽고 '읽기 시작'을 누르고 싶다.
- 근거: REQ-038, 039 · Q-018, Q-019
1. 서재 작업 화면은 좌우 분할 없이 한 줄로 위→아래: ① 편지 ② 매칭·답장·엽서 ③ 힌트·발송.
2. 위쪽에 처리할 회차 목록(`letter_arrived`, 편지 없는 `awaiting_letter`)이 오래된 순으로 보인다. 하나를 고르면 편지 전문(편지 없는 회차는 가장 최근 편지 + "이번 달 편지 없음" 표시)이 보인다. 열람만으로는 상태가 바뀌지 않는다.
3. [읽기 시작] → 회차 `reading`, 손님 창가 촛불이 켜진다.
- REJ-34: 이미 `reading` 이후 회차 → [읽기 시작] 없음
- REJ-35: 편지가 한 통도 없는 회원 → 해당 없음 (신청 때 첫 편지가 필수)
- REJ-11 (권한)
- INV: INV-09, INV-10, INV-13

### US-17: 책방지기로서, 손님에게 맞는 책을 보내기 위해, 작업 화면 중간에서 서점 책을 검색해 매칭하고 답장·엽서를 붙이고 싶다.
- 근거: REQ-040, 041 · ASM-008, Q-024, D-013, D-019, D-024, D-025

2. 책 1권을 고른다(바꿀 수 있음).
3. 답장 편지를 쓰고, 손글씨 엽서 사진 1장을 올린다(선택).
4. 작성 내용은 저장되어 화면을 떠났다 와도 남아 있다.
- REJ-36: 검색 결과 0 → "찾는 책이 없습니다"

### US-18: 책방지기로서, 책을 보내고 손님에게 코드를 이어 주기 위해, 아래쪽에서 힌트를 쓰고 발송 버튼을 누르고 싶다.

2. [발송] → 6자리 코드 자동 생성, 재고 1 차감, 회차 `shipped`, 손님 창가에 우체통 불빛.

- REJ-39: 매칭 책·답장·힌트 중 하나라도 없음 → [발송] 비활성, 빠진 항목 안내

- REJ-41: [발송]을 두 번 누름 → 코드·차감은 한 번만

### US-19: 회원으로서, 상자를 열기 전 스포일러 없이 설렘을 지키기 위해, 블라인드 북을 보고 상자 속 코드를 입력해 언박싱하고 싶다.
- 근거: REQ-025~030 · ASM-009, ASM-010, D-013, D-016
1. 나의 서가에 `shipped` 회차가 실루엣 표지 + 힌트 문장 + 코드 입력칸으로 보인다. 제목·표지·저자·답장·엽서는 없다.
2. 6자리 숫자를 직접 입력하고 [열기].
3. 맞으면 실루엣이 걷히며 표지·제목·저자가 드러나고, 아래로 답장 편지와 엽서 사진이 펼쳐진다. 회차 `unboxed`.
- 관찰 가능한 행동: 맞는 코드 확인 후 2초 안에 표지 공개 전환이 끝나고 답장이 보인다. 움직임 줄이기 설정이면 즉시 표시.
- REJ-42: 틀린 코드 → "코드가 맞지 않아요" + 남은 시도 횟수, 책 정보 미노출
- REJ-43: 실패 횟수 초과 → 일정 시간 입력 막힘 + 다시 시도 가능 시각 안내 (수치 →ARCH-03)
- REJ-44: 6자리 숫자가 아님 → 제출 안 됨
- REJ-45: 다른 회원의 코드 → 틀린 코드와 같게 처리
- REJ-46: 해지·종료된 회원 → 이미 발송된 회차는 언박싱 가능 (D-016)
