## 2. 범위 통제 근거 (KANT-C3)
전체 범위(로그인·결제·구독·관리자 포함)를 유지하면서 일정 차질을 막는 방법이다. 사용자는 2주 작업 기간 기준으로 완성품을 요구했다(D-001).
1. **KANT 증빙 경로를 먼저 완성한다.** M1(메인·목록·상세·잘못된 ID·컴포넌트 분리·Mock)이 끝나야 다음으로 간다. 이후 단계가 늦어져도 R1~R9 증빙은 이미 있다.
2. **마일스톤마다 참고 타임박스를 둔다.** 넘기면 남은 항목·이유를 보고하고 계속한다(범위는 줄이지 않음). 마일스톤 경계마다 `npm run build`가 통과해야 다음으로 간다.
3. **마일스톤 안에서도 Must → Should 순서.** 핵심 흐름이 먼저 끝까지 동작하고, 보조 화면은 그 뒤에 붙는다.
4. **외부 연동은 테스트 모드로 시작한다.** 토스페이먼츠 결제·자동결제, 카카오·네이버 로그인은 테스트 환경에서 시연한다 (D-002). 실결제 전환은 사업자 계약 후 별도 작업.
5. **의뢰서에 없는 기능은 Won't.** 추가는 사용자 승인으로만 (D-004~006 사례).
6. **콘텐츠는 임시 원고.** 소개 글, 구독료, 배송비, 환불 규정, 사업자 정보는 "예시" 표시 문구로 두고 공개 전 교체 (Q-013, Q-015). 원고 대기로 일정이 멈추지 않는다.
