# 02. 숨은 전제·가정·질문 (PM-ASM)

- 입력: PM-INV (REQ-ID로만 참조), IN-KANT. UX-CTX-ORCH 미배포.
- 판정: `명시됨` / `암묵적 전제` / `모호` / `누락`
- ASM 상태: `(미확인)` = 질문 답변 전, 범위 확정에 쓰지 않음 / `(확정)` = 답변 또는 근거로 확정

## 2. 가정·전제 목록

### ASM-001 (확정)  ← REQ-018, REQ-T03, REQ-T04
- 내용: "정기구독"의 주기, 회차당 책 수, 자동결제 여부가 없다.
- 위험: 구독·결제 데이터 구조와 결제 연동 방식(정기결제 계약 필요 여부)이 이 답에 따라 바뀐다. 되돌리기 비용 큼.
- 질문: Q-001
- 영향 계층: [모듈 협력 구조] [인프라]

### ASM-002 (확정)  ← REQ-019, REQ-022, REQ-023, REQ-039
- 내용: 편지를 처음 신청할 때 한 번만 쓰는지, 회차마다 새로 쓰는지 없다. 창가 흐름(편지 도착→촛불)은 회차마다 편지가 있다고 전제한다.
- 위험: 편지와 회차의 관계가 정해지지 않으면 촛불 상태의 기준이 없다.
- 질문: Q-002
- 영향 계층: [모듈 협력 구조]

### ASM-003 (확정)  ← REQ-033, REQ-036
- 내용: "바로 해지"할 때 이미 결제된 회차, 책방지기가 읽기 시작한 편지, 발송된 책을 어떻게 처리하는지 없다.
- 위험: 환불 분쟁, 결제 후 미발송.
- 질문: Q-003
- 영향 계층: [모듈 협력 구조]

### ASM-004 (확정)  ← REQ-013, REQ-014, REQ-021, REQ-043
- 내용: 장바구니로 산 책(단건 주문)을 손님이 어떻게 확인하고 책방지기가 어디서 처리하는지 없다. 관리자 화면 설명은 구독자 관리뿐이다.
- 위험: 주문이 들어와도 책방지기가 알 방법이 없음.
- 질문: Q-004
- 영향 계층: [어플리케이션]

### ASM-005 (확정)  ← REQ-009, REQ-040
- 내용: 책 정보와 "책방지기 노트"를 누가 어디서 입력하는지 없다. 의뢰서의 관리자 화면에는 책 등록 기능이 없다.
- 위험: 노트를 쓸 곳이 없으면 REQ-009를 운영할 수 없다. 반대로 등록 화면을 넣으면 의뢰서에 없는 기능이 추가된다.
- 질문: Q-005
- 영향 계층: [어플리케이션]

### ASM-006 (확정)  ← REQ-013, REQ-016
- 내용: 소셜 로그인만 있으므로 주문·구독은 로그인 후에만 가능하다고 전제됨. 장바구니를 비회원에게 허용하는지는 없다.
- 질문: Q-006
- 영향 계층: [어플리케이션]

### ASM-007 (확정)  ← REQ-007, REQ-008
- 내용: 책 한 권이 테마 하나에만 속하는지, 여러 테마에 걸칠 수 있는지 없다.
- 위험: 상품 데이터 구조가 달라진다.
- 질문: Q-007
- 영향 계층: [레이어]

### ASM-008 (확정)  ← REQ-040
- 내용: 구독으로 보내는 책은 서점이 판매하는 책 목록에서 검색해 고른다. 근거: "서점 책을 검색해 매칭".

### ASM-009 (확정)  ← REQ-029, REQ-042
- 내용: 6자리 코드는 발송 1건당 1개이며 재사용되지 않는다고 전제됨.
- 위험: 숫자 6자리면 경우의 수 100만 개 → 무차별 대입 가능 (D4).
- PM 요구(확정): 코드는 로그인한 손님 **본인의 발송 건**에만 대조한다. 입력 실패 횟수 제한을 둔다. 제한 수치·방식은 →ARCH-03.
- 영향 계층: [모듈 협력 구조]

### ASM-010 (확정)  ← REQ-025, REQ-026, REQ-030

- PM 요구(확정): 코드 확인 전에는 책 제목·표지·답장·엽서 사진이 손님에게 가는 응답에 포함되지 않는다(INV 후보). 방식은 →ARCH-04.

- 확정: 언박싱하면 창가는 다음 회차 편지를 기다리는 처음 상태로 돌아간다 — [자율] D-010, 근거 Q-002 답변
